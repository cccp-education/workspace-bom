== Pièges à retenir (cumul + S-240)

1. *Version dérivée ≠ version publiée* : bumper le toml local d'un borough
   (ex. `bakery = "0.0.20"`) est OBLIGATOIRE pour qu'une release porte les
   changements — un artefact Central du même numéro peut être périmé (HTOWN S-218,
   mordu S-240 : CI résolvait bakery 0.0.19 sans feature NAV).
2. *Gradle 9.8.0* : wrappers workspace bumpés (S-240, 97 wrappers, méthode S-095
   properties only).
3. *Gradle 9 API* : publication catalog = plugin `version-catalog` +
   `from(components["versionCatalog"])`. `MavenPublication.versionCatalog {}` N'EXISTE PLUS.
4. *Versions fantômes* : epub3 `3.0.1` n'existe pas Central (→ 2.2.0).
5. *nmcp collision* : NE JAMAIS re-invoquer publishAggregationToCentralPortal
   sans vérifier repo1 d'abord (2 bundles même coordonnée — mordu S-215).
6. *Gardes épinglent les versions* (BOM + conventions + contrats) — après
   CHAQUE bump toml, bump la garde dans le même commit.
7. *Polling repo1* : ~4-30 min après « deployment is publishing » (AUTOMATIC) —
   plus lent que la moyenne pour bakery (18 min S-240).
8. *Catch-22 D8 (anti-ghost)* : une entrée catalogue exige que le plugin soit
   DÉJÀ publié Central. Pour un plugin jamais publié, publier le plugin d'abord.
