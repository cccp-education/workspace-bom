== 2. `XF-FP3-3` — capacité `TracedArticleTranslator` (fin du downcast)

*Constat* : depuis `XF-FP3-1`, `BatchDocumentTranslator` testait
`documentTranslator is DocumentTranslator` — un couplage à l'implémentation
concrète (DIP violé) pour accéder aux diagnostics.
*Livré* :

[source,kotlin]
----
public interface ArticleTranslator { fun translate(...): String }

public interface TracedArticleTranslator : ArticleTranslator {
    fun translateOutcome(asciidoc: String, sourceLanguage: String, targetLanguage: String): DocumentTranslation
}
----

`DocumentTranslator : TracedArticleTranslator` ; `TranslationTrace` et
`DocumentTranslation` deviennent **publics** (type de retour de la capacité) ;
`TreeTranslationAdapter` reste un simple `ArticleTranslator` (il ne produit pas de
diagnostic par bloc) ; `BatchDocumentTranslator` fait un `when (is
TracedArticleTranslator)` — plus aucune référence au type concret.
*Test* `BatchDocumentTranslatorTraceTest` (2) : un faux `TracedArticleTranslator`
qui **n'est pas** un `DocumentTranslator` alimente le rapport ; un traducteur sans
la capacité n'écrit aucun rapport. **RED prouvé par compilation**
(`Unresolved reference 'TracedArticleTranslator'`).

== 3. `XF-FP3-2` — les diagnostics du livre ne sont plus jetés

*Constat* : `BookTranslator` créait son propre `DocumentTranslator` et **jetait** la
trace de chaque page ; un livre traduit pouvait contenir un tableau cassé sans
aucune trace.
*Livré* :

. `BookTranslator.translate(..., onPageTrace: (BookSection, TranslationTrace) -> Unit = { _, _ -> })`
   — **seam** (callback) : le traducteur reste **sans état**, l'appelant possède son
   accumulateur. `translateBody` passe par `translateBlocksOutcome` (l'API retournée
   de `XF-FP3-1`) et remonte la trace **une fois par page**.
. `BookValidationReports` (objet pur) : écrit `book-<lang>-table-validation-report.json`
   et/ou `book-<lang>-plantuml-validation-report.json` **seulement si** la trace est
   non vide (Ink Economy Law : pas de fichier = « rien à signaler »), et **par
   langue** (un run multi-langue n'écrase pas le rapport `fr` avec le `en`).
   Réutilise les schémas JSON existants (`TableValidationReport`,
   `PlantUmlValidationReport`) — un seul contrat pour les consommateurs.
. `BookTranslationRunner` accumule `Map<ref, trace>` (dédoublonnée par `ref`) puis
   écrit les rapports à côté du livre.
. **`TranslatedBook` mémoïse `bodyResolver` par `ref`** : un livre illustré est
   assemblé **deux fois** (découverte des scans, puis `:imagesdir:` relatif) et
   l'ancienne version **re-traduisait toutes les pages** (2× le coût LLM, et deux
   traductions potentiellement différentes pour le même contenu !). La mémoïsation
   garantit « une traduction par page » et rend la collecte de traces exacte.
*Tests* `BookValidationReportsTest` (3) : rapport tableau par langue, rapport
PlantUML par langue, trace propre → **aucun fichier**. **RED prouvé par
compilation** (`Unresolved reference 'BookValidationReports'`).
