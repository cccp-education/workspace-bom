== 1. Revue de code (lecture seule, 2 audits)

=== 1.1 Temps de tests — 10 constats

. Le corps des tests n'explique pas la durée d'un job (5-42 s de scénarios pour ~200 s).
. **Coût fixe par job** : setup 16-23 s + daemon 8-15 s + configuration 21-42 s +
  compile 5-30 s + un « gap » constant ≈ 30 s avant `Test`.
. **15 compilations rejouées** (une par shard) ; les artefacts Gradle
  (`generated-gradle-jars` 185 Mo, `kotlin-dsl` 86 Mo, `dependencies-accessors`)
  sont régénérés à chaque job et **absents du cache commun**.
. Les shards BDD **compilent `src/functionalTest`** (30 fichiers / 7 100 lignes) pour
  2 symboles partagés.
. **179 builds Gradle imbriqués** (TestKit) ; le test-kit home vit dans
  `build/tmp/<task>/work` (953 Mo-2,5 Go) et n'est **jamais caché** → 118 jars
  re-résolus par job.
. **Contention TestKit** : un test-kit home par tâche partagé par 3 forks → verrous ;
  cause la plus plausible de la variance ×5 des durées par classe.
. **Kover instrumente tout le classpath** (aucun `include=`), `showStandardStreams`
  actif sur les shards functional.
. Cache commun : `~/.m2` (1,7 Go, jamais alimenté) + **21 écrivains** (budget 10 Go).
. `unit` lance `test` puis `nodeTest` (2 `--no-daemon` = 2 configurations).
. **À ne pas refaire** : rééquilibrage des shards functional (2 mesures non
   concluantes), plus de 21 jobs (file > pool), cache `setup-gradle` (falsifié).

=== 1.2 Paradigme fonctionnel — 7 constats

* `codebase` (225 fichiers) et `readme` (9) déclarent Arrow **sans l'utiliser** ;
  `arrow-fx-coroutines` inutilisé chez bakery/slider.
* `bakery` et `slider` utilisent `Either`, mais **zéro** `Raise`, `NonEmptyList`,
  `Validated`, `Resource`, `IO` : ni accumulation, ni bracketing.
* Candidats prioritaires : `slider.pipeline.DeckContextValidator` (validateur à
  sortie unique), `bakery.ConfigResolver` (accumulateur mutable + casts
  positionnels) + `DomainResolver`, `planner.IntentionPlanner` (`var lastError`,
  retry, `throw`), `slider.SlidePublisher` (4 vérifications scellées + nettoyage),
  `codebase.QualityRetryCircuit`, `codebase.OcrTask`, `codebase.store.RagVectorStore`
  (`try/finally`, `!!`, `runBlocking`).
* **Loi N0 confirmée** : 9 contrats N0 en `kotlin-stdlib` only (seule exception
  documentée `agent-contracts` + koog). Arrow en N0 ferait fuiter une dépendance
  tierce via `api` → **N0 sans Arrow**, sealed maison conservés.

== 4. XB-FP-2 — pilote arrow (slider) ✅

`slider-gradle/slider-plugin`, commit `a4daf82`, **CI verte `41256091035`**.

* `DeckContextValidator` : les 8 vérifications deviennent des **fonctions pures
  indépendantes** rendant `List<String>` (vide = ok), **concaténées** — plus
  d'accumulateur mutable, plus de court-circuit sur la première erreur.
* Résultat interne `Either<NonEmptyList<String>, String>` (`arrow-core` déjà
  présent) ; `validate()` **fold** vers le `ValidationResult` historique (message
  joint par `"; "`) → **API publique inchangée**, Arrow interne (D3/D4).
* `Either.catch` capture l'échec de parsing ; les erreurs irrécupérables (JSON
  blanc / malformé / non-objet) restent en court-circuit (légitime).
* 3 tests ajoutés : tous les champs manquants signalés ensemble, `name` **et**
  `email` signalés ensemble, `validateEither` porte une `NonEmptyList`.
* Aucun changement N0, aucun changement de dépendance, aucun test lent ajouté
  (17 tests en 0,018 s + 3).
