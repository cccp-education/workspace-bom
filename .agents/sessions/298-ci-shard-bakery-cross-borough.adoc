== Livré

=== US-1 — Matrice cross-borough : 4 checks + 16 shards bakery

`.github/workflows/test.yml` — le job `borough-check` passe de 5 entrées à **20**.
Chaque entrée porte désormais `kind` / `borough` / `dir` / `task` :

* `kind: check` (4) — `api-key-pool`, `dashboard`, `planner`, `slider` : inchangés
  (`./gradlew check --no-daemon`).
* `kind: shard` (16) — `bakery-gradle` / `bakery-plugin` :
** `test` (unit)
** `functionalTestShard{A..F}` (6)
** `cucumberTestShard{JbakeCoreFoundations,JbakeCoreComponents,JbakeCorePipelines,LensTree,SiteTree,LangSwitchCore,LangSwitchEcosystem,I18nMassPipeline}` (8)
** `nodeTest`
Chaque shard clone **uniquement** `bakery-gradle`, exécute sa tâche, puis téléverse
son `bin-reports/*.ic` (`nodeTest` : pas de `.ic`, `coverage: false`).

Le workflow définit `CI: "true"` au niveau global : les tâches shard sont
`onlyIf { System.getenv("CI") != null }` — sans cela, un shard serait silencieusement
sauté et laisserait un rapport vide.

=== US-2 — Job `bakery-coverage` (fusion kover, seuil bloquant)

Nouveau job `bakery-coverage` (`needs: borough-check`) : clone `bakery-gradle`,
`download-artifact pattern: kover-ic-bakery-*` (`merge-multiple`) dans
`bakery-plugin/build/kover/bin-reports`, puis
`./gradlew koverXmlReport koverThresholdCheck -x <test/functional/cucumber/node + tous les shards>`.
Le seuil **85 %** reste bloquant. Parité de couverture : le `check` monolithique
n'agrégeait que `test + functionalTest + cucumberTest` (`e2eTest` n'est **pas**
dans `tasks.check{}`, ligne 354 de `bakery-plugin/build.gradle.kts`), soit exactement
l'union des shards — le seuil passe sur la même surface.

=== US-3 — Garde `verifyCiMatrixCoverage` étendue

`build.gradle.kts` : la garde parse maintenant les entrées `kind`/`borough`/`dir`/`task`
et vérifie :

. les entrées `check` couvrent **exactement** les boroughs testables non shardés ;
. les entrées `shard` couvrent **exactement** `bakeryShardTasks` (liste explicite =
   couplage assumé workspace-bom ↔ bakery), exhaustif et disjoint (anti « test fantôme ») ;
. le job `bakery-coverage` existe et `needs: borough-check` ;
. aucun borough inconnu ; aucun borough testable perdu (checks ∪ {bakery} == testableProjects).

`runAllTests` (Exec par borough) reste **intact** pour l'usage local.

== Leçons

. Un job monolithique cross-borough paie la **somme** ; une matrice paie le **max**
   (S-297) ; un **shard** fin paie `plus long shard + fusion` (S-298).
. La **fusion kover inter-jobs** (upload/download des `.ic` + `-x` des tâches Test)
   est la clé qui a débloqué le sharding : la mesure de couverture devient un
   **job terminal** du pipeline, pas une propriété du job de test.
. Le couplage workspace-bom ↔ bakery est **assumé et verrouillé** : workspace-bom
   invoque des noms de tâches par chaîne ; la garde `verifyCiMatrixCoverage` les
   compare à `bakeryShardTasks`, donc un shard retiré/renommé côté bakery **casse
   la CI workspace-bom** au lieu de disparaître silencieusement.
. Les tâches shard sont `onlyIf { CI != null }` : le workflow **doit** exporter
   `CI: "true"` explicitement, sinon les shards se sautent et la coverage explose.
