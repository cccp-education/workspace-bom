== 1. XF-FP2-6 — N0 `ValidationOutcome` (breaking, publié)

**Motif** (livre ch. 5.1.2 + docs `/typed-errors/`) : `Result<Unit>` est un
`Either<Throwable, A>` déguisé — il **efface le type d'erreur**, ne peut pas porter
**plusieurs** problèmes, et force l'appelant à parser un message. Sur un contrat de
validation, c'est le mauvais outil.

**Livré** (`agent-contracts`, kotlin-stdlib only — N0 sans Arrow) :
[source,kotlin]
----
data class ValidationProblem(val code: String, val message: String)

sealed interface ValidationOutcome {
    data object Valid : ValidationOutcome
    data class Invalid(val problems: List<ValidationProblem>) : ValidationOutcome {
        init { require(problems.isNotEmpty()) }
    }
}
----
`AgentTool.validate(input): ValidationOutcome` (au lieu de `Result<Unit>`).

  invariant non-vide, égalité par contenu).
