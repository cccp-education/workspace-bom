= Session 360 — GBL-014-5 : rollout du canal de publication (23 dépôts)
:date: 2026-11-15
:scope: workspace-bom (propriétaire GBL-014) + 21 dépôts publics consommateurs
:statut: ✅ migration poussée — 15/21 dépôts avec CI verte, 6 sans CI, `bakery` reporté

== Contexte

La session 229 (globale) ouvre la mission GBL-014-5 : projeter le canal de
publication (`-Pchannel=jitpack|central`, défaut `jitpack`) sur **tous** les
dépôts publics qui portaient encore le shim `conventions-plugin:0.0.17`
(`capsule` et `slider` faits aux S-227/S-083, `magic-stick` = exception).

Constat d'ouverture (mesuré sur disque) : **51** `settings.gradle.kts` portaient
le shim (49 en `0.0.17`, 2 en `0.0.16` — `bakery`), répartis sur **22 dépôts**.

== Modèle appliqué (identique à `capsule`/`slider`)

[source,kotlin]
----
// GBL-014 — the publication channel is a build property, never a branch.
val publicationChannel = providers.gradleProperty("channel").getOrElse("jitpack")

if (publicationChannel == "jitpack") {
    // CNV-16 — … (commentaire historique conservé)
    pluginManagement.repositories.maven("https://jitpack.io")
    pluginManagement.resolutionStrategy.eachPlugin { … useModule("…:0.0.18") }
}
…
if (publicationChannel == "jitpack") {
    dependencyResolutionManagement.repositories.maven("https://jitpack.io")
}
----

* Le dépôt JitPack **et** le shim ne sont déclarés que sur le canal `jitpack` ;
  en `central` le build résout les markers `education.cccp.*` et ne contient
  aucune coordonnée JitPack (`ChannelConsistency` le vérifie).
* Shim bumpé `0.0.17|0.0.16` → **`0.0.18`** ; `verifyChannel` (conventions
  0.0.18) est câblé à `check` **dès que `-Pchannel` est explicite**.
* `ci/run.sh` : `channel="${CHANNEL:-jitpack}"`, `-Pchannel="$channel"` sur
  chaque invocation Gradle ; `verifyChannel` ajouté aux jobs qui n'exécutent pas
  `check`/`build` **et** dont le build applique `.publishing`.

== Échecs préexistants (stash-prouvés, hors périmètre)

* `bureau-plugin` : `compileTestKotlin` échoue sur
  `com.github.cccp-education.workspace-bom:workspace-bom:0.0.136` introuvable —
  le build déclare ses propres `repositories {}`, qui **supplantent** le
  `dependencyResolutionManagement` des settings. Repro­duit à HEAD (stash) →
  ce n'est pas la migration. Correctif = projeter les `repositories` du build
  sur le canal.
* `agile-gradle` (root) : `Unresolved reference 'libs'` (build DSL sans
  catalogue) — baseline documentée ; `agile-plugin` n'a ni wrapper ni settings.
* `ticket-plugin` : ni wrapper ni settings (stub de bootstrap).

== Cas `bakery` — reporté (décision motivée)

`bakery` est le seul dépôt où le **mélange est structurel** : le catalogue `ws`
vient de JitPack, mais le build importe `platform("education.cccp:workspace-bom:…")`
**et** des coordonnées Central en dur (`education.cccp:document-plugin`,
`plantuml-plugin`, `api-key-pool:0.0.1`, `i18n-contracts:0.0.4`,
`plantuml-contracts`, plus 4 `platform(...)` dans les source sets). Le retrait du
`platform` seul laisserait des versions manquantes (`document-plugin` sans
version) ; la projection complète = ~6 coordonnées + 4 plateformes + le
catalogue. C'est une **US dédiée** (risque build Kover/Node/e2e), pas une étape
mécanique. Recommandation : `GBL-014-5b` (projection coordonnées `bakery`), ou
bascule `channel=central` quand US-7 sera ouverte.

== Découvertes pour US-4 (gardes)

* `verifyChannel` n'existe **que** dans les builds qui appliquent
  `education.cccp.build.publishing`. `academy`, `dashboard`, `jhipster`,
  `bureau`, `container-provision` (plugin-publish direct + `.lint`) n'ont donc
  **aucune** gate de canal disponible aujourd'hui — leurs settings sont migrés
  mais non gardés. À couvrir par US-4 (ou en enregistrant `verifyChannel` dans
  `.lint`).
* `ChannelConsistency` est **textuel** : en `central`, le corps du
  `if (publicationChannel == "jitpack") { … }` contient encore les chaînes
  `https://jitpack.io` et `usemodule(` et déclencherait `FORBIDDEN_*` si la
  configuration aboutissait (elle n'aboutit pas : markers non publiés). À
  traiter en US-4 (audit sémantique ou marqueur).
