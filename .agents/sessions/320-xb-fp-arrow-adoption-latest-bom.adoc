== 3. XB-FP-3 — bakery : accumulation sans état partagé ✅

Commits `8ed6d84d` (refactor) + `2953f951` (catalogue 0.0.117 → Arrow 2.3.0).
CI verte `41259485451`.

* `DomainResolver.resolveOutcome()` rend un `Outcome(value, error?)` **immuable**
  construit par `Either.catch(...).fold(...)` ; `resolve(MutableList)` reste en
  **déprécié** (compatibilité des appelants/tests).
* `resolveAllDataDriven` : **un binding typé nommé par domaine** (plus de
  `List<DomainResolver<*>>`), erreurs assemblées en une fois par `listOfNotNull` ;
  **plus de `MutableList`**, plus de `@Suppress("UNCHECKED_CAST")` ni de
  `resolved[0] as FirebaseProjectInfo`. Comportement identique (fallback par
  domaine, tous les échecs remontés).

== 4. XB-FP-4 — planner : erreurs typées + retry fonctionnel ✅

Commit `4d8db65` + correctif `5013280` (catalogue ROOT). CI verte `41259762865`.

* `PlanningError` (sealed) : `LlmFailure` / `ParseFailure` (tentative, détail, cause).
* `callLlm` : **`fold` pur** sur `1..MAX_ATTEMPTS` portant
  `Either<PlanningError, Plan>` — plus de `var lastError`, plus de `for`/`try`,
  arrêt dès le premier `Right`. L'`IllegalStateException` (marqueur `[FATAL]`,
  attendu par `DecomposeIntentionPluginTest`) reste **une seule fois** à la frontière.
* `LifecycleAdapter.toContextReady`/`toPlanned` : `try/catch` → `Either.catch`,
  frontière nullable inchangée (`LifecycleAdapterTest`).
* **Piège corrigé** : CI construit `:planner-plugin` **depuis la racine** → les
  accesseurs `libs` viennent du catalogue **racine**, pas du catalogue standalone
  `planner-plugin/`. Le premier push était vert en local (build standalone) et rouge
  en CI (`Unresolved reference 'arrow'`). Ajout au catalogue racine, vérifié par
  `./gradlew :planner-plugin:compileKotlin` depuis la racine.
