== 1. bakery — `LocalizeSeoHeadFunctionalTest` : 10 builds → 3

Le défaut : neuf tests, chacun lançant `gradle localizeSeoHead` pour **une**
assertion (≈ 44 s). Les règles de réécriture étaient déjà pures
(`LocalizedSeoHead`, `DocumentDirection`, `I18nTemplateLayout`) ; la seule règle
restée dans la tâche était la **sélection** du répertoire `og-images/{lang}/`.

Baby-step strict :

. **RED** (compilation) : `compileTestKotlin` —
   `Unresolved reference 'OgImageLanguage'` (×7 sites) sur
   `OgImageLanguageTest` (7 tests : propre si présent, sinon référence, jamais un
   voisin, référence absente, langue/blanc rejetés).
. **GREEN** : `bakery.seo.OgImageLanguage.resolve(language, defaultLanguage,
   available)` — objet pur, zéro I/O ; la tâche garde **une** sonde disque
   (`availableOgLanguageDirs`) et délègue la décision.
. **BDD** : `69_seo_head_locale.feature` +2 scénarios (« le répertoire est le sien
   quand il existe sur disque », « variante sans cartes → référence ») et un step
   `the head is localised for … with the available og directories …` qui rejoue la
   sélection comme la tâche.
. **REFACTOR** : `LocalizeSeoHeadFunctionalTest` = **1 smoke bout-en-bout**
   (layout `i18n/{lang}/templates`, head de référence sans préfixe, repli disque
   vers `fr`, `dir=rtl`, idempotence sur un second run) + **1 test** de la surface
   publiée (groupe `transform`). **3 builds** au lieu de 10.

Dette latente révélée au passage (stash-prouvée, préexistante) : `ktlintCheck`
est **rouge à HEAD** (le CI n'exécute jamais `check` chez bakery, seulement les
shards et `test`). Les dix appels `DomainResolver` de `ConfigResolver` (S-320)
violaient `argument-list-wrapping` : reformatage mécanique dans un commit séparé.
Le gate reste rouge sur 5 fichiers `src/main` + 12 fichiers `src/test`
préexistants → EPIC `MEM-LINT-GATE` ouvert au BACKLOG (aucune correction en
masse : `ktlintFormat` global a déjà sinistré 126 fichiers en S-231/S-244).

== 2. graphify — `IncrementalFunctionalTest` : 11 builds → 7

Six tests, onze builds : le contrat « cache hit » **rejouait** le second run du
test d'identité byte-à-byte, et « fichier modifié » / « fichier supprimé »
étaient deux paires de runs pour un même concern (l'état du disque après édition
et suppression). Fusion sans perte d'assertion :

* identité byte-à-byte **+** cache écrit **+** types de nœuds canoniques
  (`project`, `directory`, `file`, `section`) — un seul couple de runs ;
* modification **et** suppression dans le même couple : la nouvelle section
  apparaît, le nœud du fichier disparu ne subsiste pas, le voisin est intact ;
* cache corrompu (dégradation) et opt-in désactivé : inchangés.

Aucune production modifiée : les règles de fingerprint (fast path, drift,
réutilisation par hash, élagage) restent pinnées par les tests purs
`graphify.fingerprint.*`.

== 3. slider — `GenerateDeckPipelineFunctionalTest` : 7 builds → 3

description localisée EN) et les **deux gardes d'entrée** (subject manquant, LLM
injoignable) — comportement de tâche, non simulable en pur.
