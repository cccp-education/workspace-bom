== 2. Constat (audit)

[source,kotlin]
----
val tableValidationResults: MutableList<TableValidationResult.Invalid> = mutableListOf()
val plantUmlValidationResults: MutableList<PlantUmlValidationResult.Invalid> = mutableListOf()
val translationFailures: MutableSet<String> = linkedSetOf()
private var currentTopLevelIndex: String? = null
fun clearTranslationFailures() { translationFailures.clear() }
----

Quatre défauts, du plus bénin au plus grave :

. **État qui s'échappe** : les trois collections sont `public` et mutables ; le
  contrat « lis puis vide » est une convention non vérifiée par le compilateur
  (`ContentTranslationService` appelait `clear()` avant chaque lot, `BatchDocumentTranslator`
  vidait après chaque fichier).
. **Champ ambient** : `currentTopLevelIndex` sert de canal implicite pour attribuer
  un échec LLM au bloc de premier niveau ; la récursion est impure par effet de bord.
. **Fuite entre documents** : une instance réutilisée sans `clear()` hérite des
  diagnostics du document précédent (le `translate()` ne vidait que les *failures*,
  pas les résultats de validation).
. **Course de données** : `translateParallel` (jusqu'à N coroutines `Dispatchers.IO`)
  ajoutait à un `LinkedHashSet` non synchronisé — des résultats pouvaient être perdus.

== 3. Design (DDD/FP)

Nouvelle valeur immuable, **retournée** avec le résultat :

[source,kotlin]
----
internal data class TranslationTrace(
    val translationFailures: Set<String> = emptySet(),
    val tableValidationResults: List<TableValidationResult.Invalid> = emptyList(),
    val plantUmlValidationResults: List<PlantUmlValidationResult.Invalid> = emptyList(),
) { fun merge(other: TranslationTrace): TranslationTrace }

internal data class DocumentTranslation(val content: String, val trace: TranslationTrace)
internal data class ArticleTranslation(val article: PivotArticle, val trace: TranslationTrace)
internal data class BlocksTranslation(val blocks: List<PivotBlock>, val trace: TranslationTrace)
----

* La récursion (`translateBlock` → `BlockTranslation`, `translateInlines` →
  `InlinesTranslation`, `doTranslate` → `FieldTranslation(text, failed)`) devient un
  **fold qui retourne** sa trace ; l'index de bloc de premier niveau est **passé en
  paramètre** (plus de champ ambient).
* `validateTranslatedTable` / `validateTranslatedPlantUml` **retournent** le constat
  (et lèvent en `STRICT` **au même point** qu'avant : comportement observable
  inchangé — même exception, même premier constat, arrêt de la traduction).
* Les entrées publiques `translate` / `translateBlocks` restent des **coquilles**
  (`…Outcome(...).content|.blocks`) ; nouvelles entrées `internal …Outcome(…)`
  pour les appelants qui ont besoin des diagnostics.
* `ContentTranslationService` possède désormais **son** accumulateur de run
  (`ConcurrentLinkedQueue`), alimenté par les traces retournées : `drain…` —
  consommé par **bakery** (`MigrateContentI18nTask`) — est inchangé, mais
  l'accumulation n'est plus partagée avec le traducteur (et devient thread-safe).
* `BatchDocumentTranslator` lit la trace retournée au lieu de vider les propriétés.

=== 4 bis. Découverte — bug latent corrigé (fallback d'un bloc préservé)

Dans `translateArticleWithDelta`, le repli d'un bloc **préservé** (delta sans
version précédente disponible) appelait `translateBlock(...)` **sans** positionner
`currentTopLevelIndex` : un échec LLM sur ce repli n'était donc **jamais** enregistré,
le bloc était figé `TRANSLATED` — exactement le défaut que `DOC-TRANSLATE-RESILIENCE`
combat. Le paramètre `topLevelIndex` étant désormais explicite, ce repli est attribué
comme les autres. Aucun test existant n'était sensible (le scénario n'était pas couvert) ;
comportement corrigé, pas de régression.
