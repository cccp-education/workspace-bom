== 3. Livré — garde N0 (exécutée par le job CI `n0-contracts`)

Domaine pur, sans YAML, sans I/O : `contracts.ci` dans `agent-contracts/src/test`.

[cols="2,4", options="header"]
|===
| Élément | Rôle

| `CiShellAudit` (object) | `blocks(text)` → `List<ShellBlock>` ; `findings(text, source)` → `List<ShellFinding>`
| `ShellBlock` / `ShellFinding` (sealed) | `NoErrexit` (R1) et `SwallowedGate` (R2)
| R1 `NoErrexit` | bloc `run: \|` **multi-commandes** qui invoque un gate sans `errexit` : la dernière commande (souvent un `echo` de rapport) décide du code de sortie
| R2 `SwallowedGate` | gate neutralisé par `\|\| true` / `\|\| echo`, y compris à travers une continuation `\`, **hors** step `continue-on-error: true`
| `CiExitCodeGuardTest` | garde de régression sur **les** `.github/workflows` + `.github/actions` du dépôt (0 finding) + preuve anti-vide (le glob voit bien `test.yml` et une action)
| `ac_7_ci_shell_gates.feature` + `CiShellGatesSteps` + `CiShellGatesCucumberRunner` | 5 scénarios `@ci-shell-gates` (pattern S-082), tâche dédiée `ciShellGatesCucumberTest` câblée à `check`
|===

Décisions de modèle (pourquoi un audit textuel et pas un parseur YAML) :

. Le contrat est le **fichier**, pas une bibliothèque : zéro dépendance ajoutée,
  lisible en revue, et l'audit tourne dans le build N0 autonome (pattern 0124).
. **Folding des continuations** avant les règles : sans lui, les longues
  invocations `./gradlew … \ -x …` (plantuml, readme, workspace-bom) seraient des
  faux positifs — 5 findings fantômes mesurés au premier passage.
. `run: >` (scalaire replié) = **une** commande : jamais un bloc (2 faux positifs
  `koverThresholdCheck` évités).
. Les mots-clés de shell (`if`/`then`/`fi`/`for`/`do`) ne sont pas des commandes.
. `continue-on-error: true` rend la neutralisation explicite → exemptée.

=== Correctif imposé par la CI (run `41363590010` rouge)

Le premier run de clôture a **échoué** : `CiShellGatesCucumberRunner › The historical
false green is detected` — `Expected size: 1 but was: 0`. Cause : `RUN_LITERAL`
n'acceptait que la forme clé de mapping (`        run: |`) et **pas** la forme item
de séquence (`      - run: |`) utilisée par les steps de workflow — le parseur ne
voyait donc aucun bloc dans les workflows, seulement dans les actions composites
(forme clé). Unité et BDD ne pouvaient pas le voir puisque les deux utilisaient la
même forme fautive.

Correctif (fichier test-only, **aucun** changement de production) :

. `RUN_LITERAL = ^([ \t]*)(?:-[ \t]+)?run:[ \t]*\|.*$` — groupe = indentation de
  l'item (YAML exige un contenu plus indenté) ; vérifié hors test sur JDK 25
  (`Pattern` : `      - run: |` → groupe 6 espaces ; `      - name: x` → aucun).
. Test unitaire dédié « a run block declared as a sequence item is parsed ».
. **Garde anti-vide durcie** : `CiExitCodeGuardTest` vérifie désormais que le
  `test.yml` **réel** produit des blocs non vides et au moins un bloc avec
  `errexit` — sans quoi la garde pouvait être verte sur un parseur aveugle
  (leçon : la preuve anti-vide doit porter sur le **parseur**, pas seulement sur
  le glob).

Deuxième run (run `41364183166`) : rouge sur `:test`, `a gate neutralised by a
fallback is flagged` — le finding portait la ligne YAML (`- run: ./gradlew check
|| true`) au lieu de la commande shell. Correctif `shellOf()` (strippe le préfixe
`- run: ` **avant** d'appliquer R1/R2, lignes de continuation inchangées).

**Run final `41364710329` ✅ 21/21 jobs** (N0 inclus) : `:test` +
`cucumberTest` + `versionCatalogCucumberTest` + `ciShellGatesCucumberTest` verts.
La boucle rouge → diagnostic → correctif → re-push est la procédure EAGER
(« une invalidation imposée par un run CI rouge se corrige en local par
compilation, puis re-push ») ; zéro test lancé localement.
