== 2. Cache CI commun au dépôt + CI-1.4 (Ollama)

=== 2.1 Dépendances — un seul cache partagé par tous les jobs

Deux actions composites nouvelles, utilisées par **tous** les jobs du workflow
(garde de matrice, 4 `check`, 15 shards bakery, job de couverture fusionnée,
2 entrées N0, job Ollama) :

* `.github/actions/setup-common-cache` — `actions/cache/restore` sur
  `~/.gradle/caches/modules-2`, `~/.gradle/caches/jars-9`,
  `~/.gradle/wrapper/dists`, `~/.m2/repository`, avec une **clé glissante**
  (`cccp-common-<os>-<epoch>-<run_id>-<attempt>-<job-index>`) et un
  `restore-keys: cccp-common-<os>-<epoch>-` : chaque job restaure le snapshot le
  plus récent, quel que soit son répertoire de travail ou son borough.
* `.github/actions/save-common-cache` — `actions/cache/save` en **dernière étape**
  (`if: always()`) sous une clé unique par job : le pool se renouvelle à chaque run,
  et un cache évincé (> 7 j) est simplement remplacé par le plus récent.

`gradle/actions/setup-gradle@v4` passe en `cache-disabled: true` : son cache est
indexé par fichiers de build (donc par répertoire de travail), ce qui **duplique**
exactement ce que le cache commun supprime. Il reste utilisé pour l'instrumentation
et la validation de wrapper.

Preuve dans le run `41248220277` : étape `Restore the repository-wide common cache`
OK dans chaque job et log `Cache saved with key: cccp-common-Linux-v1-…`.

archivés). **Reprise verbatim** de la version la plus récente (plantuml), adaptée
aux valeurs de gouvernance : modèle `qwen3:0.6b`, port `11466`.

* `.github/actions/setup-ollama/action.yml` — cache image (`ollama-image-<os>-<image>`)
  + cache modèles (`ollama-models-<os>-<model>`), démarrage, `pull` seulement si

* `env` global : `OLLAMA_TEST_PORT=11466`, `OLLAMA_TEST_MODEL=qwen3:0.6b`

Le cache GitHub est **scopé au dépôt** : tous les jobs de `workspace-bom` partagent
donc les mêmes octets (image + poids), ce qui est exactement la demande. Entre
dépôts, seul un runner self-hosted partagerait réellement (cf.
`.agents/CADRAGE_CI_CACHE.adoc`).

=== 3.2 US-3 + US-5 — une seule garde statique

`verifyCrossBoroughPins` (`build.gradle.kts`, groupe `verification`, câblée à
`check`) : tout pin **consommé** par un build frère (catalogues de versions +
pins `workspace-bom:<v>` / `workspace-catalog:<v>` dans les scripts de build) doit
être **≤ la version publiée par ce BOM**. Un pin `-SNAPSHOT` est rejeté (US-3), un
catalogue en retard sur un consommateur est rejeté (US-5). Zéro réseau, zéro modèle
Gradle ; les builds frères absents sont ignorés (la CI clone un borough par job),
et le pin de l'artefact **produit** par un build est exclu (une version de dev peut
légitimement précéder sa publication).

*RED prouvé deux fois* : `codebase = "9.9.9"` dans slider ⇒ « newer than the
published catalogue `codebase-plugin = 0.0.18` » ; `workspace-catalog:0.0.999`
dans readme ⇒ « newer than the published `workspace-bom = 0.0.116` ». GREEN :
`51` catalogues frères + `130` scripts de build, `29` pins auto-produits ignorés.

Découverte : `plantuml` dans un toml consommateur est le **moteur** PlantUML
(`1.2026.0`), pas le plugin — alias retiré de la table (faux positif évité).
