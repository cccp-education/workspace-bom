== Contexte

Session de maintenance cross-borough déclenchée depuis cheroliv.com (S-058).
Question pilote : « est-ce que bakery utilise la dernière version de document et
est-ce que cheroliv utilise la dernière version de bakery ? »

Audit de la chaîne réelle :
`cheroliv.com → runner-gradle (N3) → bakery-plugin (N2) → document-plugin`.

**Faille trouvée** : `bakery-plugin 0.0.20` (publié S-247) importait
`workspace-bom:0.0.58`, dont la constraint figeait `document-plugin:0.0.18` —
alors que document 0.0.19 était déjà publié Central (S-276). Tout consommateur
de bakery **sans** le workaround du runner résolvait donc document 0.0.18.

C'est la classe de bug du **piège #13** (drift catalogue MEMPHIS) : le pin
`platform workspace-bom` d'un borough n'a pas été bumpé lors de la release
bakery 0.0.20.
