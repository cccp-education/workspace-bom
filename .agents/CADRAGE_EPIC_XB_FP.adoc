== Objet

Deux demandes pilote traitées comme **une seule EPIC transverse** :

. **Optimiser le temps des tests** de la CI cross-borough (chemin critique mesuré :
   shards bakery ~3m30-4m + coverage ~1m45 + file de runners).
. **Refactoriser les implémentations vers un paradigme fonctionnel** (arrow-kt),
   sans casser la loi N0 (contrats sans dépendance externe) ni les gates CI.

Le porteur est MEMPHIS parce que l'EPIC est **transverse** (elle traverse N0 → N2,
plusieurs boroughs) et que le workspace-bom est la source unique de vérité des
versions (dont `arrow 2.2.2`). Chaque US est exécutée **dans le borough concerné**
(1 US = 1 session du borough), avec preuve CI du borough.

=== Loi N0 (confirmée, non négociable)

Les contrats N0 sont des builds standalone **kotlin-stdlib only**
(`codebase-contracts:18`, `i18n-contracts:19`, `ocr-contracts:19`… ; seule exception
documentée : `agent-contracts` expose `koog-agents`). Importer arrow en N0 :

* ajouterait une dépendance tierce aux artefacts publiés ;
* la ferait **fuiter** dans les signatures publiques (`api`) vers N1→N4 ;
* couplerait l'évolution des contrats à l'API d'Arrow.

**Décision** : N0 reste **sans Arrow**. Un contrat qui a besoin d'un type de
résultat définit son **sealed type** (déjà le cas : `ContextChannel`,
`AgentState`, `Metadata`, `ValidationResult`…). La conversion `sealed ⇄ Either`
se fait **à la frontière N1**.

=== Abstraction maison à réutiliser (ne pas remplacer par du générique)

`slider.pipeline.ValidationResult`, `slider.content.ContentAssertionResult`,
`slider.translation.TranslationResult`, `slider.repository.DeployError`,
`codebase.finetuning.FineTuningResult`, `codebase.rag.MetadataValidator.ValidationResult`,
`codebase.quality.QualityVerdict`, `codebase.store.DoubtExposure`,
`codebase.koog.pipeline.PipelineGraph`, `bakery.ConfigResolutionError`,
`bakery.GitService.PrePushValidation`, `readme.GitValidationResult`.

Doctrine : **Arrow pour la composition** (accumulation d'erreurs, capture
d'exception, bracketing, retry) ; **types scellés maison pour le vocabulaire
métier** ; conversion à la frontière.

== 2 bis. Arrow — version et BOM (documentation officielle)

* **Dernière version** : `2.3.0` (`arrow-core`, `arrow-fx-coroutines`, `arrow-stack`
  — marqueur `release` de Maven Central, confirmé par
  https://arrow-kt.io/learn/quickstart/setup/).
* **Arrow publie son propre BOM** : `io.arrow-kt:arrow-stack:2.3.0` (docs officielles,
  section « Using a Bill-of-Materials (BOM) »). Il versionne toute la pile
  (`arrow-core`, `arrow-fx-coroutines`, `arrow-optics`, `arrow-atomic`,
  `arrow-resilience`, `arrow-collectors`, …).
* **Intégration retenue** : le BOM `workspace-bom` **importe** `arrow-stack`
  (`api(platform(...))` hors `constraints`, ce qui produit
  `<type>pom</type><scope>import</scope>` dans le POM publié) et conserve les pins
  explicites des composants réellement utilisés. Le catalogue expose l'alias
  `arrow-stack`.
* `arrow-integrations-jackson-module` **n'est pas dans le stack** (versionnage
  séparé) : reste épinglé à `0.15.1` (dernière version) pour `slider`.
* Bumps appliqués : BOM `0.0.116 → 0.0.117`, `slider` 2.2.2 → 2.3.0, `planner`
  (adoption, 2.3.0), `bakery` via le BOM, `codebase`/`readme`/`plantuml` conservent
  les dépendances restaurées (l'objectif est l'**adoption**, pas la suppression).

== 3. Décisions (D1 → D12)

. **D1** — L'EPIC est **transverse**, portée par MEMPHIS, exécutée US par US dans
  le borough concerné (1 US = 1 session du borough).
. **D2** — **N0 sans Arrow** (loi ci-dessus). Sealed maison conservés.
. **D3** — Arrow autorisé en **N1/N2** uniquement, en dépendance `implementation`
  (jamais `api` d'un contrat).
. **D4** — **Réutiliser** les types scellés maison comme frontière publique ;
  Arrow reste **interne** (ex. `internal fun validateEither`).
. **D5** — **Pilote** = `slider.pipeline.DeckContextValidator` (pur, 17 tests en
  0,018 s, arrow-core déjà présent, rayon d'action = 1 objet + 1 test).
. **D6** — Comportement du pilote : **accumulation** des erreurs
  (`Either<NonEmptyList<String>, String>`) au lieu du premier échec ; message
  joint par `"; "` ; aucune rupture des assertions existantes (`.contains`).
. **D7** — **Mesurer avant d'optimiser** : tout changement de performance CI est
  précédé d'une mesure (durées par job/étape, `--profile` sur un shard).
. **D8** — Cache commun : ajouter les **artefacts Gradle** (`generated-gradle-jars`,
  `kotlin-dsl`, `dependencies-accessors`), retirer `~/.m2/repository`, et limiter
  les **écrivains** (1 par famille de dépendances) au lieu de 21.
. **D9** — **Ne pas ajouter de jobs** (pool ~20-21) ; ne pas rééquilibrer les
  shards functional (mesures non concluantes) ; ne pas ré-activer le cache
  `setup-gradle`.
. **D10** — Découpler les shards BDD de la compilation `functionalTest`
  (source set partagé) : US dédiée, côté bakery.
. **D11** — TestKit : répertoire **hors `build/`**, caché, par fork si la
  contention est confirmée : US dédiée, côté bakery.
. **D12** — **Adoption d’Arrow aux seams réels** (et non suppression) : chaque dépôt qui déclare Arrow doit l’**utiliser** à un seam identifié (accumulation, capture d’exception, retry borné, bracketing). Une dépendance déclarée sans usage est une **dette d’adoption** à traiter par une US, pas une raison de retirer l’outil. `codebase` (QualityRetryCircuit), `readme` (JGitRemoteValidator) et `bakery`/`planner`/`slider` sont les seams retenus ; `plantuml` reste un seam différé (API `KnowledgeGraphParser` à faire évoluer).
