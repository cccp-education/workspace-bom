:type: hygiène de build (iso-comportement)
:origine: warn CI `codex-gradle` (session 236) — `tasks.registering` déprécié Gradle 9.6

== Objet

`MEM-WARN-FREE` (S-329→S-333) a soldé les warnings de **compilation Kotlin**
(478 → 0). Il reste une famille distincte, invisible de cet inventaire : les
**dépréciations des *build scripts* Kotlin DSL** émises par Gradle lui-même
(`w: file:///…/build.gradle.kts:<ligne> … is deprecated`).

Symptôme déclencheur (CI `codex-gradle`, S-236) : `tasks.registering(Test::class)`
avec délégué `by` émet **3 warnings par occurrence** (Gradle 9.6 → Gradle 10) :

----
w: …/build.gradle.kts:216:34: '…RegisteringDomainObjectDelegateProviderWithTypeAndAction…provideDelegate…' is deprecated.
w: …:216:34: '…C.registering(type: KClass<U>, action: U.() -> Unit)…' is deprecated.
w: …:216:34: '…ExistingDomainObjectDelegate…getValue…' is deprecated.
----

Ce bruit masque les vraies régressions de build (même logique que
`MEM-WARN-FREE`), et **Gradle 10 cassera** ces API.

== 2. Décisions

. **D1 — Zéro `@Suppress` / `-nowarn` / baseline.** On migre vers l'API
  documentée ; un warning non migrable est **consigné** (famille tierce) avec
  sa raison, jamais masqué (doctrine `MEM-WARN-FREE`).
. **D2 — `registering` → `register<T>(name) { }`.** Le délégué `by` disparaît
  (`val task = tasks.register<Test>("…") { … }`). La variable reste utilisable
  pour `configure`/`dependsOn` via `TaskProvider` (aucun changement de graphe).
. **D3 — `buildDir` → `layout.buildDirectory`.** `buildDir = …` →
  `layout.buildDirectory.set(…)` ; `File(buildDir, …)` →
  `layout.buildDirectory.dir(…).get().asFile`.
. **D4 — `kotlinOptions` → `compilerOptions`.** (dépôt privé `edster-app`,
  hors périmètre public si le pilote ne l'ouvre pas → US conditionnelle).
. **D5 — Gate = garde statique, pas un parse de log.** Une tâche
  `verifyNoDeprecatedBuildScripts` (conventions-plugin, testée sur fixtures)
  scanne les `.kts` frères pour les motifs F1/F2 et échoue avec un message
  actionnable. Pas de `--warning-mode=all | grep` (fragile, dépend des versions
  Gradle/Kotlin).
. **D6 — 1 borough = 1 US.** Chaque US est iso-comportement, mesure avant/après
  dans le log CI du commit, zéro changement de tâche/DSL public.
. **D7 — Ordre par bruit.** `codex` d'abord (déclencheur, 33 lignes de warnings
  CI), puis `academy`, `conventions`, `plantuml` (F1) ; F2 en second lot (dont
  `workspace-bom`, `slider`, `codebase`, `bakery`).
. **D8 — Hors périmètre assumé** : `configurations.all`, `sourceSets.getByName`,
  `training-catalogue-site` (site, pas un plugin) si non Gradle 10-bloquant →
  audit séparé si un warning réel apparaît.

== 4. Risques

[cols="1,3,2,2", options="header"]
|===
| ID | Risque | Impact | Mitigation

| R-01 | Un `registering` capture une variable utilisée plus loin → `TaskProvider` au lieu de `Task` | Build cassé | Compilation + `tasks --dry-run` ; le type `TaskProvider` expose `configure {}`
| R-02 | `buildDir` lu dans une closure exécutée tôt | Chemin nul | Migrer vers `layout.buildDirectory.get()` au point d'usage
| R-03 | Le warning vient d'un **plugin tiers** (conventions) et pas du build script | Faux positif | Mesure dynamique ; si tiers → consigné, pas de `@Suppress`
| R-04 | Gate statique qui rate une nouvelle forme (`named<T>`, `registering` importé) | Faux vert | Fixtures négatives dans le test de la garde (anti test fantôme, S-269)
|===
