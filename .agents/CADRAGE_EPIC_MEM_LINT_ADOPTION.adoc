== Objet

La session 324 a soldé `MEM-LINT-GATE` chez **bakery** : `ktlintCheck` était rouge
à HEAD (32 violations) parce que son CI ne lançait jamais `check`. L'audit de
sortie (« vérifier si un borough est réellement aveugle ») a montré un problème
**plus large** : la convention `education.cccp.build.lint` (ktlint 1.5.0 +
detekt) n'est appliquée que par **bakery** et **conventions-gradle**. Les autres
boroughs n'ont **aucune analyse statique** — ni ktlint, ni detekt — et rien ne
les en empêche.

style. Deux sous-populations :

  container-provision, review, flow).

== 2. Ce que le pilote a prouvé (graphify, S-325)

* `education.cccp.build.lint` 0.0.7 câble `ktlintCheck` dans `check` → comme le CI
  lance `./gradlew build`, **aucun workflow à modifier** (vérifié :
  `check --dry-run` contient 4 tâches ktlint ; CI verte `41268477861`, 2m00s).
* **647 violations** dans 39 fichiers (trailing-comma 124, function-signature 113,
  multiline-expression-wrapping 101, argument-list-wrapping 65, blank-first-line
  62, wrapping 37, string-template-indent 36, chain-method-continuation 23, …) :
  `ktlintFormat` les corrige **toutes** sauf les wildcard imports.
* Les **wildcard imports** (`kotlin.io.path.*`) ne sont pas auto-corrigeables :
  expansion manuelle (5 symboles en main, 4 en test).
* Un `.editorconfig` **tracké** avec `root = true` est indispensable (sinon un
  checkout CI isole et retombe sur les défauts — leçon bakery V10).
* **Piège de garde** : `ktlintFormat` reflue `version =\n  ws.versions.x.get()` ;
  une garde qui parse le fichier ligne à ligne casse par accident (famille
  S-244 F34, reproduite S-325 sur `GraphifyPluginPublicationTest`). Toute garde
  qui lit un script de build doit être **whitespace-insensitive**.

== 3. Décisions

. **D1** — 1 borough = 1 session (pattern 1 US = 1 session + CI du borough).
  **AMENDÉ S-327 (décision pilote « enchaine les boroughs en parallèle tant que
  le DAG le permet »)** : l'adoption est **indépendante par dépôt** (forêt, pas
  chaîne) → les boroughs peuvent être exécutés **en vagues parallèles** ; la seule
  contrainte est la **RAM de la machine** (vagues de 2, daemons arrêtés entre vagues).
. **D2** — Ordre : d'abord les boroughs au **gate gratuit** (CI `build`/`check`),
   du plus petit au plus gros ; ensuite ceux qui exigent une step CI.
. **D3** — `.editorconfig` tracké, `root = true`, copie de bakery (max_line_length
   160) ; aucune divergence de règles entre boroughs.
. **D4** — Baseline ktlint **vide** : les violations se corrigent, elles ne
   s'exemptent pas (doctrine S-244). La garde de bakery (baseline sans `<file>`)
   est le modèle.
. **D5** — `ktlintFormat` acceptable **si et seulement si** `git status` = les
   fichiers signalés par `ktlintCheck` (preuve de non-collatéral).
. **D6** — Toute garde qui lit un `build.gradle.kts`/`settings.gradle.kts` doit
   être **whitespace-insensitive** (D3-robustesse).
. **D7** — Vestiges (`newpipe`, `notebook`) et boroughs `0 fichier .kt` : **hors
   périmètre** tant qu'ils ne produisent pas de code.

== 5. Risques

[cols="2,4", options="header"]
|===
| Risque | Parade
| Reformater hors périmètre | D5 : `git status` = exactement les fichiers signalés par `ktlintCheck`
| Garde cassée par le reflow | D6 : whitespace-insensitive (prouvé S-325)
| Adoption cosmétique (gate non exécuté) | D2 : vérifier que `check --dry-run` contient les tâches ktlint **et** que le CI les atteint ; sinon step explicite
| Gros diff illisible | Commits séparés : `build(lint)` (convention + .editorconfig + format) puis `test(guard)` ; le diff est mécanique
| Dette ktlint qui revient | Baseline vide + garde de test (modèle bakery S-324)
|===
